# Conversion and check scripts

These scripts made the LiteRT graphs, the host files and the public check set of d1-omni-600M-LiteRT, and ran every check reported for it. They ran on a Mac (Apple M4 Max, 128 GB, macOS 27.0) and one Samsung Galaxy S26 (SM-S942Q, 12 GB, Android 16) on 2026-10-08. The phone runs they prepared and scored used the measurement app in `../android/d1omni_gate/` and, for the NPU legs and the second set of GPU legs, a C-API runner on LiteRT 2.2.0 (not included).

Every LiteRT run goes through the CompiledModel API (`ai_edge_litert.compiled_model` on the Mac; the Kotlin API and the C API on the phone). Each script's docstring gives its commands and what it writes; this file gives the order.

## Work directory

The scripts find their work directory `W` as the parent of their own folder (`W/scripts/` is a copy of this folder) and name it `d1_omni_work` in their docstrings. They write `W/fixtures/`, `W/ref/` (the reference), `W/out/` (graphs), `W/results/`, `W/device/` (phone inputs and records), `W/cache/`, `W/logs/` and `W/ship/` (the repository as uploaded). `W/host/` holds the host of the repository (`../host/` here). The model is read from the Hugging Face cache at revision `414f8d6438174f5b2133a9c21a478fc42625e308`.

## Environments

Three Python environments; the docstrings call them `venv-ref/bin/python`, `~/venvs/lt094dev/bin/python` and `venv-ship/bin/python`.

- Reference (`$REF`): Python 3.12.11, torch 2.14.1, transformers 5.19.0, torchvision 0.29.1, numpy 2.5.3, tokenizers 0.23.2, safetensors 0.8.0, soundfile 0.14.0, huggingface_hub 1.33.0, Pillow 12.3.0. Runs the provider's own code (`trust_remote_code=True`) with 12 torch threads.
- Export (`$EXPORT`): Python 3.14.6, litert-torch 0.9.4, litert-converter 0.4.0, ai-edge-litert 2.2.0, ai-edge-quantizer 0.9.0, torch 2.13.0, numpy 2.5.2. Exports, stores fp16 weights, runs the desktop checks and the timings.
- Host (`$HOST`): Python 3.12.13 and `host/requirements.txt` (ai-edge-litert 2.2.0, numpy 2.5.3, tokenizers 0.23.2, Pillow 12.3.0, soundfile 0.14.0). Runs the shipped host, its tests and its check.
- The fixture speech (six clips) was synthesised with Kokoro-82M (kokoro 0.9.4, torch 2.13.0).

The timing scripts and the GPU checks ran one at a time on an otherwise idle machine (a lock kept other heavy jobs off it; that wrapper is not included). Each timing set started only when no other process used more than 120 % CPU and the CPU was at least 50 % idle (`timing_mac.py`).

## Commands in order

1. Environment and source files: `$REF scripts/env_record.py`, `$REF scripts/fetch_small.py` (the source repo's small files, sha256 checked), `$REF scripts/tok_check.py` (token ids, the escape rule, the tokenizer adapter of the host against `AutoTokenizer`).
2. Fixtures: `$REF scripts/fx_define.py` (uses `own_long.py` for the long-state record) writes `fixtures/requests.json`; `$REF -I scripts/media_fetch.py --download-dir <empty dir>` fetches the photos (Wikimedia Commons, CC0) and checks every file's sha256; `kokoro_synth.py` synthesises the speech; `$REF scripts/encode_rows.py` encodes every question with the provider's `prompt.encode()`. The full check set also carries records shared with another conversion of the same model and records under other licences; the publishable subset is `../fixtures/public_*.json`, which `host/verify.py` reads.
3. Reference: `$REF scripts/ref_probs.py --verify-weights`, then `$REF scripts/ref_probs.py` and `$REF scripts/ref_probs.py --rerun-images` (images resized on the float path, as torchvision 0.24 does it) → `ref/records_ref.json` (the provider's float32 probabilities, logits and prefixes for every record).
4. Module checks: `$REF scripts/eager_check.py --ckpt` (the graph module `d1_graph.D1Decision` against the provider: probabilities, float64 identity, pad and bucket invariance); `$REF scripts/norm_probe.py` (every norm's largest sum of squares over the fixtures → `results/norm_range.json`); `$REF scripts/f16safe_check.py --k-table` and `$REF scripts/f16safe_check.py` (the per-site scale k of the fp16-safe rewrite, `d1_graph_f16safe.py`, and its float32 identity).
5. Decision graphs: `$EXPORT scripts/graph_build.py --f16safe --L <L>` for L in 128, 256, 512, 1024, 2048, 4096 (fp32 file, operator scan, signature, smoke run), then `$EXPORT scripts/quant_forms.py --L <L> --variant f16safe --forms fp16` (fully connected weights stored in fp16, the embedding table kept in float32). `$EXPORT scripts/litert_gate.py --backend cpu|gpu [--precision fp32|default] --L <L> --form fp16` checks each file against the reference on the Mac CPU and on Metal.
6. Vision: `$EXPORT scripts/vision_graph.py --keymap`, `--range`, `--write tower --variant f16safe`, `--half tower --variant f16safe`, `--write projector`, `--half projector` (the tower takes the resized position table from the host); `vision_check.py` checks the host preprocessing (`--host`), the module (`--eager`, `--truth` = float64), the LiteRT files (`--lrt`) and the end to end (`--e2e`).
7. Audio: `$REF scripts/audio_graph.py --keymap`, `$EXPORT scripts/audio_graph.py --k-table`, then for T in 501, 1001, 2001, 3001: `--build <T> --variant f16safe` and `--fp16 <T> --variant f16safe`; `audio_check.py` checks the host mel (`--mel`), the module (`--eager`, `--long`), the LiteRT files (`--lite`) and the scores (`--score`). `r12_variant_check.py audio|vision ...` runs the fp16-safe files through the same gates on the CPU and on Metal at both precisions, and `r12_variant_check.py ms` times them.
8. Mac timing: `timing_mac.py` (one call per decision bucket and the card's workloads), `r11_ms.py` (the shipped files, the end-to-end image and audio questions) → `results/timing_mac_*.json`.
9. The repository: `$EXPORT scripts/ship_build.py` assembles `W/ship/` (the twelve graphs, `contract.json`, `tokenizer.json`, `LICENSE`, `NOTICE`, `host/`, `fixtures/`) and `results/ship_manifest.json`; then `$HOST ship/host/tests.py --repo ship --reference ref/records_ref.json --requests fixtures/requests.json` and `$HOST ship/host/verify.py --repo ship --check-files [--gpu]`.
10. The two audio buckets without a reference row: `$REF scripts/r13_audio_e2e_ref.py` (the provider's float32 run of a 5 s clip and a 27.15 s clip) and `$HOST scripts/r13_audio_e2e.py` (the phone's prefixes and the Mac's shipped files end to end against it).
11. Galaxy S26, measurement app: `$EXPORT scripts/s26_rows.py` writes the input rows; `bash scripts/s26_chain.sh check|mac-baseline|run <round>` installs the app, pushes the graphs, runs the legs of `device/plan_<round>.tsv` and samples the phone's clocks, temperatures and memory every 2 s; `$EXPORT scripts/s26_score.py gate|timing|generic|e2e9|table ...` scores the legs against the reference on the Mac. `CA` must name the directory of your device-hold tools; `PY` and `ADB` default to `python3` and `adb`.
12. Galaxy S26, C-API runner (NPU and GPU legs): `$EXPORT scripts/npu_fixtures.py write|check` (inputs in the subgraph's tensor order, checked bit for bit on the Mac CPU); `bash scripts/s26_npu_chain.sh check|run <round>` (needs the runner binary and the NPU runtime libraries staged under `device/<round>/stage/`, with `LIBS_SUMS` naming their SHA256SUMS); `$EXPORT scripts/npu_score.py leg|e2e|table ...`.

Helpers: `d1_src.py` (paths, the provider's prompt and encoder modules), `litert_run.py` (CompiledModel runner, operator scan, the runtime's delegation log), `fake_runner.py` (the app's contract on the Mac CPU, which the scorer uses for its Mac baseline).
