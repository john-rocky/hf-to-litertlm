# Audio features in Kotlin that match the Python processor

An audio model's encoder reads the log-mel features its Python processor computes, and an Android app that computes them another way feeds the encoder other numbers. The formulas are not enough: on the Python side, numpy's float32 FFT rounds differently from PyTorch's in 93 % of the bins (by up to 4e-7 relative), and a mel band at the 16-bit noise floor next to loud bins turned that into up to 1.7e-4 on a speech clip's log-mel. What held was to copy each float32 step as PyTorch computes it on the CPU the reference runs on (here an arm64 Mac: SLEEF's vectorized float32 functions, pocketfft without MKL), in two stages: a numpy copy of the processor that reproduces its arithmetic step by step on that machine, then a line-by-line Kotlin port of the numpy copy. These are the steps of such a port of `Lfm3OmniFeatureExtractor` (128 mel bands, a 400-sample window, hop 160 at 16 kHz) and how it was checked.

1. **The WAV reader.** Accept and refuse what the Python side's reader does (here Python's `wave` module and the model's `read_audio`: 16-bit PCM only, in a plain or an extensible WAV file), then divide the samples by 32768 and average the channels.
2. **Fused multiply-adds.** Where the CPU build fuses `a * b + c` into one instruction (pocketfft built with clang's `-ffp-contract=on`, SLEEF's FMA paths), round it once to float32: the double product of two floats is exact, the double sum is rounded once, and the one double-rounding case (a sum on a float midpoint with a nonzero TwoSum error) moves one double step toward the true sum first.
3. **Sine, cosine and the base-10 logarithm.** SLEEF's float32 functions at 1 ULP (`sinf_u1`, `cosf_u1`, `log10f_u1`) with their FMAs, not the JVM's `Math` functions (a correctly rounded log10 differs from SLEEF's in 0.1 % of the values by one ulp); keep sin(−0) = −0. They feed the window, the logarithm and the resampling filter.
4. **The window.** `torch.hann_window(400)` is periodic: cos(k · float32(2π / 400)) · −0.5 + 0.5 in float32, with SLEEF's cosine.
5. **The FFT.** The plan PyTorch runs without MKL: pocketfft's `rfftp` for the window length's factors (400 = 4 · 4 · 5 · 5, so `radf4` and `radf5`), in float32 as pocketfft computes it, twiddle factors included, not a generic FFT. Then |X| as `torch.abs` of a complex64 (hypotf), squared in float32.
6. **The mel filters and the logarithm.** The filters in double as transformers' `mel_filter_bank` builds them (slaney scale and norm); the example sums each band's products in double and rounds once; then SLEEF's log10, the floor (−12) and (x + 4) / 4, from the processor's config.
7. **A clip at another rate.** torchaudio's default resample (Hann-windowed sinc, 6 zero crossings, roll-off 0.99) with its filter in float32. The Python side applies the filter as one float32 matrix product (Accelerate on the Mac), whose order of additions the example does not copy: it sums each output in double and rounds once, and on a 44.1 kHz stereo clip the features differed by 2.6e-4. Refuse a rate whose filter would need more than 1,000,000 values (44,101 Hz, for example) rather than build it.
8. **Check the port on the desktop JVM before the phone.** A JVM test reads the same WAV files and the features the Python side wrote as `.npy` (read `fortran_order` from the header: numpy can write a transposed view in Fortran order) and asserts the largest difference per clip. Here: at most 2.4e-7 on 22 clips at 16 kHz and 2.6e-4 on the 44.1 kHz stereo clip after resampling; the reader took and refused the same 10 test files as the model's reader, with the same samples.

Worked example: [`d1-omni-2b/`](https://github.com/john-rocky/LiteRT-Models/tree/main/d1-omni-2b) in LiteRT-Models: `app/src/main/java/com/d1_omni_2b/Audio.kt` (the reader, the resampler and the features), the JVM tests `AudioTest.kt` and `HostParityTest.kt`, and `scripts/make_fixtures.py`, which writes the Python side's features. The numpy copy it ports is [`host/d1_audio_features.py`](https://huggingface.co/litert-community/d1-Omni-2B-LiteRT/blob/main/host/d1_audio_features.py) in the model repository.
